# WarpforgeOpenServer

A local stand-in for Warpforge's deleted PlayFab title (`A3CCB`). The BepInEx plugin in `../NetLogger` redirects every `*.playfabapi.com` request here.

## First time only: trust the HTTPS certificate

The game connects over HTTPS, so Windows has to trust the local development certificate. Run this once and click **Yes** on the Windows security prompt:

```bash
dotnet dev-certs https --trust
```

## Run

```bash
dotnet run
```

Run it from this folder, and leave it running while you play. It listens on `https://localhost:5443` (used by default) and `http://localhost:5080`.

Each request is printed to the console and saved to `logs/requests.log`:

- **green:** handled
- **yellow `UNHANDLED`:** the game called something that has no real implementation yet. It got an empty success response. Implement these next.
- **grey `3rd`:** a Firebase or Unity Gaming Services request the plugin sent here instead of to Everguild's projects (`/_thirdparty/<host>/...`)
- **red `???`:** a request that didn't match `POST /<Api>/<Method>`

## Data you can edit (restart the server after editing)

| File | What it is |
|---|---|
| `data/player.json` | Your account: display name, user data, read-only data, inventory, currencies, statistics |
| `data/titledata.json` | PlayFab title data as `"Key": "string value"`. The game probably keeps a lot of config here. |
| `data/responses/<Method>.json` | Replaces the `data` part of the response for any PlayFab method, e.g. `GetCatalogItems.json` |
| `data/cloudscript/<FunctionName>.json` | Becomes the `FunctionResult` of an `ExecuteCloudScript` / `ExecuteFunction` call with that name |
| `data/thirdparty/remoteconfig.json` | Replaces the Unity Remote Config response (default: `EnableTroopVOs` and `EnableWarlordVOs` on) |

The canned-file overrides let you try a response without changing any code.

`data/liveops/*.json` (live-op events) and some `titledata.json` keys are generated by `../Tools/gen_liveops.py`. Edit the script and rerun it rather than editing those files by hand.

## Known gaps

The new-player tutorial now completes, but these parts of the old server are still missing:

- **Campaign node rewards.** `CollectCampaignRewards` marks the node as claimed and charges its points, but grants no items. Node rewards are booster packs, wildcards, drop tables, cards and currency. The game looks most of these up in title-data configs that are still empty (`ShopConfig.containers` and `dropTables`, `WildcardConfig.wildcards`). The reward window shows "Item not found" for them for the same reason. The drop tables can be built from `../extracted/DropTableItem.json`. No source for the wildcard and booster-pack data has been found yet.
- **Campaign points.** Matches don't award campaign points. Every player starts with `StartingCampaignPoints` (200) shared points in `Api.cs`, which is only enough for the tutorial's second node. Match results should award points the way the old server did.
- **Other armies' campaigns.** Only the Ultramarines campaign map was found in the game bundles (`extracted/CampaignNodeData.json`). The other 12 armies get a 3-node placeholder chain.
- **Missions.** There is only the daily-login mission (`Daily_Login_0`), with no rewards, and the Missions tab is empty.
- **Forge.** There are no Forge events, so the Forge tab throws "Sequence contains no elements".
- **Unhandled CloudScript calls:** `UpdateMultipleMissionPoints` and `SelectActiveCampaign` get an empty result. Neither has caused a visible problem yet.
- **Ranked divisions.** `GameModesConfig.rankedRanks` in `titledata.json` is a made-up ladder, not the real one.

## Pointing the game somewhere else

The redirect target is in `<game>\BepInEx\config\local.warpforge.netlogger.cfg` under `[Redirect] PlayFabUrl`:

- Set it to `http://localhost:5080` if HTTPS fails. Unity may refuse plain HTTP, though.
- Leave it empty to turn the redirect off.
